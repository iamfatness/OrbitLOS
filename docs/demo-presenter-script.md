# OrbitLOS presenter walkthrough

## Prepare a fresh run

1. As the owner, open **Team → Create brokerage**. Choose **Create as a fictional pilot workspace**. Give each timed run its own name and keep the workspace address with the [acceptance checklist](demo-completion-checklist.md).
2. Invite the test LO and processor in **Team → Staff access**. Each uses Google sign-in at the new workspace address. Confirm the role badge and active roster entry. The borrower and realtor use their sample portal links in separate tabs.
3. In **Team → Pilot scenario**, assign the scenario to the active LO, select **Include dashboard examples for the presenter walkthrough**, and load it. Start from a freshly loaded scenario near presentation time. Keep CRM/MISMO rehearsal files in the local evidence folder and use the built-in sample PDFs.
4. Confirm the expected starting records below. Create the second fresh brokerage using the same setup. Reset can regenerate the scenario and rotate its links. Use a fresh brokerage for a full rerun so that independent campaign imports, settings, and test activity start clean too.

| Starting check | Expected result in an empty brokerage |
| --- | --- |
| LO Today | Riley Pilot Referral has an overdue first-contact deadline. Morgan Pilot Borrower is stalled. Quinn Demo Closing has a title-package item due tomorrow. |
| Owner funding | Selected month has one funded loan for $310,000 and one $340,000 projection. The prior period has one funded loan for $290,000. |
| LO production | The assigned LO sees $310,000 this month and $290,000 last month. |
| Processing | Closing workload shows Quinn Demo Closing in the current closing window. The owner can open its exact checklist item or assign the file. |
| File exceptions | Quinn Demo Closing has a homeowners insurance request due tomorrow. Open it from **Playbooks → File exceptions** to show the exact evidence request. |
| Realtor sales | Taylor Pilot Realtor has a funded loan in each period. Riley adds an open referral. For setups close to Eastern midnight or a month boundary, use Riley’s displayed intake date to reconcile the cohort. |
| Retention | Casey Pilot Past Client has a 6.125% watch target. The guide can record a sample 6.000% observation to trigger the follow-up. |

If using two signed-in accounts for the three roles, document the switch in the run log. The invited account starts as LO. After reviewing and pricing Riley, the admin reassigns the loan to the admin account, changes the invited account to Processor, assigns the processor, and sends the handoff. The invited account then signs in as processor and works the file. Use distinct LO and processor accounts when available to avoid the extra switch during a presentation.

## Run of show

1. **Owner.** Open **Reports → Funding dashboard** and compare the seeded periods. Select **Projected funding → Open loan → Open closing workbench** for Quinn. In **Sales conversion → Realtors**, trace Taylor’s funded count to the matching loan. Show the overdue referral and its owner.
2. **LO.** From Riley’s first-contact card in **Today**, choose **Open campaign** and log **Connected**. Once the call is saved, choose **Start 1003**. In the borrower tab, load the fictional answers, save and reopen the draft, then submit it. Return to the loan and mark the submitted revision reviewed.
3. **LO.** Run mock credit and carry the score into pricing. To show borrower advice, add a pricing snapshot in **Scenarios**, compare it against another option, and save a recommendation with the rationale. Open the recommended pricing option, save the sample quote, and preview the borrower version. Send the reviewed application to mock UWM and show the new condition alert. Use the alert to open the exact condition.

   For the letter-sharing demo, open **Overview → File readiness → Sample preapproval letters** on the reviewed purchase. Issue a sample, publish to the borrower and the linked realtor separately, and open each existing portal to download that version. Withdraw one audience to show how the two permissions work independently.
4. **Processor.** Accept the handoff from **Processing** and request both suggested documents. In the borrower tab, verify with the displayed demo code. Show the blocked pay-stub result before submitting the bank statement. After the retry interval, upload the clean pay stub. On the staff file, select **Request replacement**, enter a borrower message, and save. Return to the borrower checklist and use the existing verification to submit the replacement. Return to the staff checklist, accept and send both samples, and select **Check mock clearance for 2 documents**. Add a private handoff note and return the file to the LO. Use **Refresh status** or **Refresh checklist** if a tab has stale information.
5. **Owner or assigned LO.** Complete the handoff. Open **Review closing readiness** from the loan's next action and confirm **Mark Clear to Close**. Add a closing checklist item with a due date and mark it complete. Record closing, then record funding separately. For recovery, open **Rehearse follow-up recovery** and select **Simulate a follow-up failure for this funding change** before recording funding. The funding dashboard should show two loans totaling $670,000 after Riley funds at $360,000.
6. **Owner or LO.** Open the funded realtor milestone and show that the private note stays on the staff file. If simulating a failure, retry the original run in **Playbooks → Automation run history** before opening the funding follow-up. In **Closing workbench**, select **Record borrower check-in**, choose **Requested callback**, and set its date. Select **Save & start repeat 1003 → Refinance**, then open the borrower view from the new staff loan record. Record Casey’s sample rate and open the owned rate-watch follow-up.
7. **Owner.** Show the callback in Calendar and the separate purchase and refinance files in Search. Open Quinn’s insurance request from File exceptions and show the funding ledger. In Migration, preview the fictional CSV and review a synthetic MISMO draft.

Label the rate, credit, lender delivery, document checks, and outbound messages as samples or simulations as they appear. Use the actual clock for the narrated run. Record preparation and presentation times separately, the deployment ID, roles used, expected and observed figures, and any interruption. Complete the independent acceptance checks alongside the two presenter runs.
